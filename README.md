# 十点半 · 轮流坐庄（PWA）

陕西民间「十点半」，**2–4 人轮流坐庄**，支持人机对战与好友同玩。

界面与交互不是重新设计的——直接沿用已上线的「六选五」那一套：同一份 `css/style.css`、
同一套 `rp-`/`ach-`/`settle-` 组件、同一份 Canvas 牌面绘制（`js/card.js`）、
同一批 mp3 音效（`js/sfx.js`），只把游戏内核换成十点半。

## 为什么是重写而不是修补

第一版（`../ten_and_a_half`）失败在方法上：它是照着「UI 基线摘要」自己重新发明了一套
token 和布局，看着同色系，实际是另一个应用；而且动作条用 `position:absolute` 挂在舞台底部，
真机上 `innerHeight` 一变就被推出可视区，表现是「进去是空的，没有下注入口」。

这一版的硬约束：

1. **视觉资产同源**：`css/style.css`、`css/records.css`、`assets/*.webp`、`assets/audio/*.mp3`、
   `js/card.js`、`js/sfx.js` 全部从六选五原样拷贝，不手改一行。
2. **布局在文档流里**：动作条、下注档位、主按钮都是 flex 子项，不用绝对定位贴底。
3. **状态机单向推进**：`BET → DEAL → ACT（逐个闲家）→ BANKER → SETTLE`，没有跨局残留标志。
4. **输入不吞**：动画期间点「停牌」会排队（`pendingStand`），这张发完立刻执行；
   自动推进窗口（爆牌 / 十点半）用 `locked` 硬锁，防止 520ms 内被再点一次。
5. **世代号防串场**：`st.gen` 让换场/回首页后的旧定时器与旧回调自动作废。

## 跑起来

```bash
npm test                     # 40 条：规则内核 35 + 整场经济模拟 5
python -m http.server 18888 --bind 127.0.0.1
# 打开 http://127.0.0.1:18888/index.html
npm run probe                # 真实 Edge 浏览器全流程验收（52 项）
```

`tools/probe.mjs` 会在三种手机视口（390×844 / 360×640 / 412×915）下真鼠标点击走完整局，
断言下注档位的**矩形**在可视区内（不是「元素存在」），还单独验「点数 ≤6 停牌键禁用且真点击无效」，
最后做一次断网冷启动 + 离线一局。

## 规则口径

### 经济

| 项 | 值 |
| --- | --- |
| 每人起手筹码 | 50 |
| 上庄注 | 20（从庄家自己筹码里扣进庄池） |
| 闲家下注档位 | 1 / 2 / 3，只能选一档 |
| 下庄 | 庄池输到 0，或赢到 40（净赚 20） |
| 整场结束 | 有人筹码 ≤ 0，或轮到某人坐庄但筹码 < 20 |

庄池赔付能力封顶：`实赔 = min(应付, 庄池余额)`，所以**庄池永远不会是负数**，
「输完下庄」在数据上就是「赔穿到 0」。结算行会标记 `shortPaid`。

### 比牌（庄家优先，平局全部归庄）

1. 都爆 → 庄赢
2. 闲家爆 → 庄赢
3. 庄家爆 → 闲赢
4. 点数大者赢
5. 都是十点半 → 庄赢
6. 同点 → 庄赢

### 倍数（只由「闲家自己的牌型」与「庄家十点半」决定）

| 情形 | 闲家 |
| --- | --- |
| 庄家十点半并获胜 | 输 2 倍 |
| 闲家五张不爆 | 赢 3 倍 |
| 闲家五张不爆且十点半 | 赢 6 倍 |
| 闲家五张爆 | 输 3 倍（罚则优先，不再叠加庄家十点半翻倍） |

### 要牌

- 一副牌去大小王（52 张）。A=1，2–10 按面值，J/Q/K=0.5 点。
- 超过 10.5 爆牌；恰好 10.5 为「十点半」。
- **总点数 ≤ 6 必须继续要牌，不许停牌**（已爆、已满 5 张两个豁免）。
  例：起手 2 + J = 2.5 点，「停牌」按钮禁用，真点也会被拦下并提示。
- 手牌上限 5 张；一局结束发现牌堆低于 22 张就换新牌堆（一局最多用到 4×5=20 张，留余量）。

数值只允许出现在 `js/params.js`。

### 一个重要的实测数据

3 人局、闲家各下 2 注时，**庄家单局净收益 +1.48 筹码（约 25%）**，
一任庄 **99%** 是「赢够 20 下庄」，平均 14.4 局，输光下庄只占 1%。

原因是两条规则叠加：同点归庄，加上闲家 ≤6 必须继续要牌（爆牌率上升）。
这不是 bug，是规则本身的数学后果——庄是赚钱的，所以轮庄是公平的，整场筹码总量恒定。
`test/match-sim.test.mjs` 把这条钉住了：改比牌或赔付口径，这个数字会立刻动。

## 仓库与发布

两个仓库，单向同步：

| 仓库 | 可见性 | 内容 |
| --- | --- | --- |
| 私有库 | 私有 | 完整开发历史、`tools/publish-public.sh`、内部发布记录 |
| `ten-and-half-public` | 公开 | 单条脱敏快照，只收 `git archive HEAD` 导出的当前文件 |

改完代码在私有库提交，然后 `bash tools/publish-public.sh /d/ten-and-half-public`
把快照推到公开库（脚本会做敏感检查、剔除发布脚本、LF 归一、线上入口脱敏，再自检后才提交）。

**两者不能直接同步分支**：那会把全部历史连同开发日记、本机路径、线上入口一起公开。
公开库是只读镜像，不接受 PR，改动请在私有库进行。

公开库带一条 GitHub Actions（`.github/workflows/test.yml`）：push / PR 时跑 `npm test`
与 `npm run check:version`，再断言公库里不该出现发布脚本与探针产物。
私有库不跑这条 workflow —— 私有仓库的 Actions 额度已用尽，job 会以 `steps=0` 直接失败，
只会在每次 push 后留一条红叉。本地 `npm test` 仍是开发时的主闸门。

## 改动纪律（踩过的坑）

- **改 JS/CSS 必须同步改版本号**：`index.html` 与 `sw.js` 里的 `?v=` 是精确匹配的，
  版本号不变时 Service Worker 会把旧文件喂回来——本地看着「改了没生效」，线上就是旧版。
  当前版本号：`202611232c`（`index.html`、`sw.js`、`version.json` 三处一起改）。
- 探针必须用全新浏览器 profile（`tools/probe.mjs` 已自动清理），否则同样会测到旧缓存。
- 截图要等 `.screen.enter` 的 320ms 转场跑完，否则会截到半张牌桌。
- **不要用 `display:none` 收起下注条**：几何消失会让下方主按钮位移，真机手感是「刚点完确认，
  下一个键已经挪位」。用 `visibility:hidden` + `pointer-events:none` 保住几何。
- **牌扇叠压是 `shave = w × overlap`（负 margin-left）**，不是 `w × (1 − overlap)`，
  写反会让四人局 5 张牌横出一倍撑破座位。
- `node --test test/` 在 Node v22 会把目录当模块报 `Cannot find module`，
  必须写成显式文件：`node --test test/*.test.mjs`。
